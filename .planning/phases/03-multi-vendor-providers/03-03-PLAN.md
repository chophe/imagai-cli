<objective>
Make the declared format visible where operators look for it: the `imagai list-engines` table, the TUI Engines tab, and `.env.example`. No selection logic changes anywhere.

**As a** user of `imagai`, **I want to** configure named non-OpenAI-compatible providers alongside existing engines and select them per request, **so that** I can point at a vendor whose API is not OpenAI-shaped without waiting for the project to add it (ROADMAP Phase 3 **Goal:**, verbatim).

Purpose: D-32 rejected both a new `list-providers` subcommand and format-only-in-`--json`; the format belongs in the one discovery command that already exists. D-34 caps the TUI and web work at *rendering* the format in the existing engine lists — no filter, no format selector, no new controls. D-33 makes success criterion 4 (all three surfaces) true by construction: the `--engine` flag, the TUI engine row and the web `engine` field already carry a name, and only the adapter behind that name changes, so this plan deliberately adds no picker code. Plan 03-05 then proves the reachability with real requests on each surface.

A second, quieter decision lands here. `list-engines --all` fetches `GET {base_url}/models`, which fal.ai does not implement; the deferred-ideas note asked for that to be decided during planning rather than left open. The decision is **no code change**: `cmd_list_engines` already reports a failed per-engine fetch as one `[error] Failed to fetch models for '<name>': …` line and continues to the next engine, so a fal engine lists its row (with the format making the reason obvious) and the other engines still list their models. Adding a fal-specific discovery path would be new mechanism for a case that already degrades correctly.

Output: the format column on the CLI table and the TUI tab, three option labels in the SPA carrying the format, and the `FORMAT` entry in `.env.example`.

</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator env (`FORMAT`) → displayed format column | All three surfaces derive their column from one helper, so a label that misstates the format steers the operator to the wrong engine for a paid request |
| console/terminal → `list-engines` table | The table is the primary discovery surface; a truncated or overwritten column can hide an engine's real format |
| `.env.example` → operator `.env` | A template is copied verbatim by operators, so a wrong value or a real key in it propagates into live configuration |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-09 | Spoofing | `src/cli.rs::cmd_list_engines` and `src/tui.rs::engine_rows` — a format column that shows a resolved default for an engine whose declaration is broken, so the operator believes a misconfigured engine is healthy | medium | mitigate | Both surfaces call the single `crate::formats::format_label` helper, which returns the declared value verbatim when it is unrecognised; `list_engines_shows_a_broken_format_declaration_verbatim` and `engines_tab_rows_name_the_format_column` pin both branches |
| T-03-10 | Information Disclosure | `.env.example` — a real credential or an internal endpoint written into a committed template | medium | mitigate | Only the `[key]` placeholder and the public `https://fal.run` host appear; the verify gates reject any other credential shape and require the diff to be additions-only, so no pre-existing placeholder is disturbed |
| T-03-11 | Denial of Service | `src/cli.rs::cmd_list_engines --all` — a provider with no `GET /models` endpoint aborts the whole listing, hiding every other engine | low | mitigate | No code change is required and none is made: the existing per-engine `Err` arm prints one `[error] Failed to fetch models for '<name>': …` line and the loop continues, which the untouched `list_engines_all_fetches_models` test covers. The format column makes the reason legible without a new mechanism |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install in this plan: no `Cargo.toml` change, no new dependency. `colored` and `ratatui` are already dependencies audited by the Phase 1 supply-chain gate |

</threat_model>
