<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| existing engine config → OpenAI-compatible request body | The whole phase's safety argument is that an undeclared engine is untouched, so the boundary is between the new format-resolution code and the request bodies of engines that never declared a format |
| selected engine name → provider family | A request misrouted to the fal adapter for an OpenAI-compatible engine would spend credits on the wrong vendor with a body the vendor may reject |
| test assertions → claimed guarantees | A regression net that asserts a subset, or that was weakened to pass, provides false assurance about criteria 3 and 4 |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-15 | Tampering | `src/provider.rs::generate_images` — the format-resolve step at the top of the function changes the request body of an engine that declared nothing, breaking every existing engine | critical | mitigate | The fal branch is entered only behind `matches!(format, ProviderFormat::Fal)`, and `openai_default_engine_body_is_unchanged` plus `stability_default_engine_body_is_unchanged` assert full key-set equality on the captured bodies for undeclared engines. A leaked fal key fails the suite rather than reaching a provider |
| T-03-16 | Spoofing | declared-format precedence — an explicit `openai` declaration changes a transport that sniffing would have chosen, so an engine silently takes a different path after a config edit | medium | mitigate | `declared_openai_format_keeps_the_sniffed_transports` and `declared_openai_edit_engine_still_saves_with_lineage` assert that a declaration leaves the OpenRouter chat path and the gpt-image multipart path exactly where they were, so D-29 is proven rather than assumed |
| T-03-17 | Denial of Service | criterion 4's TUI half is asserted by argument rather than by a test, so a future change to the TUI selection path could silently break parity | medium | mitigate | The argument is recorded in the summary and pinned by two anchors: `engines_tab_rows_name_the_format_column` proves the format is visible in the TUI, and the shared `generate_image_core` is exercised by both the CLI and web tests, so any TUI routing change would have to alter that shared entry point and would fail those suites. The unchanged `App.engine` field is named in the summary so the reviewer can verify it |
| T-03-18 | Repudiation | the regression net is quietly weakened — a test deleted, an assertion narrowed, a test marked ignored — so the suite still passes while coverage shrinks | high | mitigate | The acceptance criteria forbid modifying or deleting any pre-existing test and require the summary to record per-suite counts before and after; the verify gate fails on any suite reporting fewer tests than it inherited. No `#[ignore]` may be introduced |
| T-03-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install in this plan: no dependency change. This plan adds tests only; `assert_cmd`, `predicates`, `tempfile`, `tokio` and `axum` are already dev/regular dependencies audited by the Phase 1 supply-chain gate |
