# Phase 2 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Phase 2 extends all three existing surfaces with the iteration lineage (BRCH-01..04). Nothing in
this phase introduces a new rendering technology: the tree is ASCII text on the CLI, ratatui
`Line`/`Span` rows in the TUI, and `<select>` options in the existing single-file SPA. Every new
visual element below is composed from primitives that already ship.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none — hand-rolled ratatui TUI + hand-written single-file SPA |
| Preset | not applicable (no `components.json`, no `package.json`, no Tailwind) |
| Component library | ratatui (Rust, terminal) / hand-written HTML+CSS (`web_interface.html`, embedded via `include_str!` at `src/web.rs:18`) |
| Icon library | none — literal emoji, matching `src/cli.rs:187-270` and `src/tui.rs:892` |
| Font | SPA body: `'Segoe UI', Tahoma, Geneva, Verdana, sans-serif`; SPA output/log: `'Courier New', monospace`; TUI and CLI: terminal-controlled, not set by this codebase |

**No build step.** `web_interface.html` is embedded at compile time; a UI change is a Rust file
edit plus recompile. There is no JS toolchain, no bundler, and no test runner for the SPA — do
not add one in this phase.

## Surface Contracts

BRCH-04 requires identical behavior across surfaces: same nodes, same order, same operations.
Ordering is fixed for all three — **root sessions newest-first, children oldest-first** (matches
`list_output_images`'s newest-first convention and D-19's "newest-first default").

### CLI — `imagai history` and `imagai fork`

`imagai history` prints one indented ASCII tree per root session. Grammar, exactly:

| Field | Spec |
|-------|------|
| connector | depth 0: none. depth ≥ 1: `+- ` for a non-last child, `` `- `` for the last child |
| indent | 3 spaces per ancestor level, then the connector |
| node id | first 8 hex chars of the node id (D-17), lowercase |
| prompt | clipped to 32 chars — first 29 chars + `...` when longer, else space-padded to 32 |
| filename | full, relative to `output_dir` (D-23), never clipped |
| timestamp | `YYYY-MM-DD HH:MM` |
| column rule | `{id8}` + 2 spaces + `{prompt:32}` + 2 spaces + `{filename}` + 2 spaces + `{timestamp}` |
| missing node | `✗ ` immediately after the connector, before the id8 |

```text
🌳 Iteration history — generated_images (7 nodes, 3 sessions)

1a2b3c4d  a cat wearing a hat               2026-10-09-cat.png           2026-10-09 11:40
`- 2b3c4d5e  make it sunset                 2026-10-09-cat-edit.png      2026-10-09 11:41
   `- 3c4d5e6f  add a party hat             2026-10-09-cat-edit-1.png    2026-10-09 11:42

9f8e7d6c  a dog on a skateboard              2026-10-09-dog.png           2026-10-09 11:45

✗ 5a6b7c8d  rainy street at night            2026-10-09-street.png        2026-10-09 11:30

[warning] 1 node points at a file that is no longer in the output directory.
```

`imagai history --json` emits the same structure machine-readable:

```json
{
  "output_dir": "generated_images",
  "nodes": 7,
  "missing": 1,
  "roots": [
    {
      "id": "1a2b3c4d",
      "parent": null,
      "filename": "2026-10-09-cat.png",
      "prompt": "a cat wearing a hat",
      "model": "dall-e-3",
      "created": "2026-10-09T11:40:00Z",
      "missing": false,
      "children": [
        { "id": "2b3c4d5e", "parent": "1a2b3c4d", "filename": "2026-10-09-cat-edit.png",
          "prompt": "make it sunset", "model": "gpt-image-1",
          "created": "2026-10-09T11:41:00Z", "missing": false, "children": [] }
      ]
    }
  ]
}
```

`--json` is the whole flag set for `history` (D-16) — no ordering, filtering, or format flags.

`imagai fork --from <image|node-id> -p "<change>"` (D-16; repeatable `--ref`, inherited from
`edit` with the 16-reference cap unchanged):

1. Resolve `--from` in this order: unique 8-hex node-id prefix → bare filename inside `output_dir`
   → if the file exists but is untracked, adopt it as a root node at fork time (D-12) — never an
   error.
2. Print `🔀 Forking from {filename} (node {id8})` on its own line.
3. Then the existing edit lines, unchanged: `🖼️ Editing image with engine: …`, `📜 Change: …`.
4. Then the existing result printing (`print_edit_results`) and the edit-path non-zero exit guard.

### TUI — History tab + picker entry

`const TABS` becomes `["Generate", "Edit", "History", "Engines", "About"]` — History at index 2,
because fork always continues in the Edit tab. Index shift is a real hazard: the `draw` and
`draw_footer` `match self.tab` arms must be re-indexed and the `_ => draw_about_tab` catch-all
replaced with an explicit index 4 arm.

Layout, mirroring `draw_edit_tab`'s 55/45 split:

```text
┌ History ──────────────────────┐┌ Node ─────────────────────────┐
│ 1a2b3c4d  a cat wearing a hat ││ id       1a2b3c4d9f8e7d6c     │
│ `- 2b3c4d5e  make it sunset   ││ file     2026-10-09-cat.png   │
│    `- 3c4d5e6f  add a hat     ││ prompt   a cat wearing a hat  │
│ 9f8e7d6c  a dog on a board    ││ model    dall-e-3             │
│ … 3 more                      ││ created  2026-10-09T11:40:00Z │
└───────────────────────────────┘│ parent   —                    │
                                 │ children 1                    │
                                 │                               │
                                 │ [ Fork edit ]                 │
                                 └───────────────────────────────┘
```

| Element | Rule |
|---------|------|
| Tree pane | `Block::bordered().title(" History ")`; one `Line` per node using the same connector/id/prompt grammar as the CLI (prompt clipped to the pane width), nodes in the same order as the CLI |
| Selected row | `▶ ` prefix + `Color::Cyan` + `BOLD`, unselected rows `Color::Gray` — exactly `draw_source_picker`'s selected-row style |
| Scroll | reuse `PickerState`'s `selected`/`scroll`/`height` triple and `picker_move`; a trailing `… {n} more` line in `Color::DarkGray` when the list is clipped |
| Detail pane | `Block::bordered().title(" Node ")`; `label {:<10}` + value rows, labels `Color::Gray`, values `Color::White` — the `label_w` idiom from `draw_edit_form`. The prompt row is the only wrapped line: `Paragraph::wrap(Wrap { trim: true })`, because prompts are arbitrary length |
| Missing node | detail shows `file ✗ <filename> (missing from disk)` in `Color::Yellow`; tree row keeps the `✗ ` marker |
| Fork action | final detail-pane row ` [ Fork edit ] `, rendered with the submit-button style (`Color::Green`; `Color::Black` on `Color::Green` + `BOLD` when the pane is focused) |
| Key hints (footer, History tab) | `q Quit | Tab switch tab | ↑/↓ navigate | Enter fork from node | p pick from history` |
| Keys | `↑/↓` and `j/k` move the tree selection; `Enter` forks the selected node; `p` forks via the Edit-tab picker path |
| Fork result | sets `edit_source` to the node's filename, switches to the Edit tab, `push_log(Info, "Source image: {name}")` — the exact log `picker_select` already emits — and leaves the change instruction to the Edit tab's prompt row |

"Pick from history" in the Edit tab source picker (D-18): `open_source_picker`'s entry list gains a
first row ` Pick from history… `. Selecting it sets `tab = History` and records that a pick is
pending (`history_pick_for_edit: bool` on `App`); `Enter` in the History tab then writes the chosen
node's filename into `edit_source`, restores the Edit tab, clears the flag, and pushes the same
info log. Escaping the picker or the History tab leaves `edit_source` untouched — the guarantee the
existing `picker_escape_leaves_source_unchanged` test already encodes.

### Web — `GET /api/history`, `POST /api/fork`, SPA history view

Routes join `router()` at `src/web.rs:113` next to `/api/edit`; handlers follow the
`#[serde(default)]` payload convention and the `{ "success": …, … }` JSON envelope.

`GET /api/history`:

```json
{ "success": true, "output_dir": "generated_images", "nodes": 7, "missing": 1, "roots": [ … ] }
```

`roots` carries the same nested node shape as the CLI's `--json`. Newest-first roots.

`POST /api/fork` request — every field optional:

| Field | Type | Rule |
|-------|------|------|
| `from` | string | 8-hex node id or bare filename in `output_dir`; refused with the standard error when it contains `/` or `\` (same `is_plain_filename` guard as `/api/edit`) |
| `prompt` | string | the change instruction; empty is rejected like `/api/edit` |
| `engine` | string | falls back to `default_engine` |
| `output` | string | filename in `output_dir`, same guard |
| `refs` | string[] | reference images, order preserved |

Response is `result_items_json` verbatim — the fork endpoint cannot drift from `/api/edit`.

SPA markup, composed only from existing classes (`.form-grid`, `.form-group.full-width`,
`.section-title`, `.help-text`, `.generate-btn`, `.output-content`, `.image-preview`) — **no new
CSS rules**:

```html
<form id="historyForm">
    <div class="section-title">Iteration history</div>
    <div class="form-group full-width">
        <select id="history_node" size="8"></select>
        <div class="help-text">One row per node, newest branch first: id · snippet · filename · time.
        Pick one and fork from it.</div>
    </div>
    <button type="submit" class="generate-btn" id="historyBtn">Fork selected node</button>
</form>
```

- `loadHistory()` mirrors `loadOutputImages()` (`web_interface.html:841`): `fetch('/api/history')`,
  rebuild option rows client-side, no re-sort. Option label = the same
  `{id8}  {prompt:32}  {filename}  {time}` grammar as the CLI tree, with tree connectors rendered
  as leading spaces so branch depth reads at a glance. Missing nodes get a leading `✗ `.
- The top option is always the sentinel `value=""` / "Pick a node to fork from"; when
  `missing > 0`, a `<option disabled>` above it reports the count.
- Submit posts to `/api/fork`, writes progress and results into the shared `#output-content` /
  `#image-preview` block, and calls `loadHistory()` on success so the new node appears without a
  reload — exactly how `executeEdit()` refreshes the pickers.
- `newest-first` is the only ordering the SPA requests; there is no client-side sort control.

| Requirement | CLI | TUI | Web |

## API & Data Shapes

| Shape | Definition |
|-------|------------|
| Node id | 8 lowercase hex chars, displayed (D-17). Prefix match on input: a unique 8-hex prefix resolves; an ambiguous prefix is an error naming the candidates |
| Node record | `{ id, parent, filename, prompt, model, created, missing, children[] }` — `parent: null` marks a session root (D-09); `created` is RFC 3339 via the existing `datetime_iso` helper (`src/web.rs:623`) |

| Store | `.imagai-history.json` inside `output_dir` (D-08), human-readable, read-modify-write per save (D-11). Not a UI concern; noted because the executor must not introduce a config surface for it |
| Trust boundary | `is_plain_filename` (`src/web.rs:246`) governs every path-shaped `/api/fork` field, exactly as on `/api/edit`; a value carrying a separator is refused, never silently reduced |

## Rules for the Executor

1. Fork reuses `generate_image_core` — do not add a parallel pipeline. `source_image` plus the
   existing `-edit` filename scheme carry the fork (D-13).
2. Draw helpers never return `Result`; failures go through `push_log` (existing convention). No
   `unwrap` outside `#[cfg(test)]`.
3. New TUI state is fields on `App` — a `HistoryState` struct next to `PickerState` is fine; a
   second overlay type is not.
4. New clap subcommands are `HistoryArgs` / `ForkArgs` in `src/cli.rs` plus two `Commands`
   variants; the handlers are `cmd_history` / `cmd_fork`.
5. No new CSS rule in `web_interface.html`; no new dependency; no new timestamp source — reuse
   `datetime_iso`.
6. Add `.imagai-history.json` to `.gitignore` so a configured `output_dir` outside
   `generated_images/` does not dirty the tree.
7. `cargo fmt` and `cargo clippy --all-targets` stay clean (project baseline).
