<objective>
Put the lineage on the command line: a tree view of every session and a fork command that starts a new edit from any past image without losing the original branch.

**As a** user of `imagai`, **I want to** view an image's iteration lineage and fork any past result into a new edit without losing the original, **so that** I can branch instead of starting over.

`imagai history` renders one indented ASCII tree per root session (D-17). `imagai fork --from <image|node-id> -p "<change>"` resolves a past image through the shared resolver, prints the fork line, then runs the existing edit path unchanged and records the child node through the hook plan 02-01 installed in `generate_image_core`. `edit` gains `--from`, the equivalent way to name a past image (D-16), so a user can step back to any branch point from either command.

Purpose: this is BRCH-01, BRCH-02 and BRCH-03's command-line surface, and it is the reference implementation of the tree grammar the TUI and SPA must match. The three error sentences live only in `history::resolve_fork_source`; this plan formats them and must not reword them.

Output: `HistoryArgs`, `ForkArgs`, `cmd_history`, `cmd_fork`, the `--from` flag on `EditArgs`, and the `tests/cli.rs` e2e coverage.
</objective>

| T-02-05 | Tampering | `src/cli.rs::cmd_fork` — `--from` resolving to a path outside `output_dir` | medium | mitigate | `history::resolve_fork_source` matches node ids and recorded filenames against records only, and a raw path is accepted only as the literal file the operator named.
