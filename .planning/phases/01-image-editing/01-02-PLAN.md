<objective>
Turn "edit my most recent image" into a real command, and make the "which image?" question
have exactly one answer in the codebase.

Today `--image` is the only way to name a source, so a user who just generated three images
has to remember a filename. This plan adds the D-03 behaviour — omit `--image` and the newest
image in `output_dir` is used, and the choice is printed — behind one shared
`list_output_images` helper that `src/cli.rs` and `src/web.rs` both call, replacing the private
`read_dir` loop that currently lives inside the web gallery handler.

Purpose: EDIT-02 is "use any past generation as the source without re-supplying its path".
It is also the helper that plans 01-03 and 01-04 need for their pickers, so it is built once,
in the shared utility module, and consumed by every surface rather than re-implemented per
frontend (the duplication the ARCHITECTURE anti-pattern section warns about).

Output: `list_output_images` in `src/utils.rs` with its unit tests, the D-03 auto-pick branch
in `cmd_edit`, `src/web.rs::list_images` refactored onto the shared helper, and the regression
tests that pin both behaviours.
</objective>
