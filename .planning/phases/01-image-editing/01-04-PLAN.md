<objective>
Complete the third surface so `imagai edit` is reachable from the terminal UI as well as the
command line and the browser.

The Edit tab gets its own row constants and its own focus/editing state rather than extending
the Generate tab's `ROWS = 11` range, a source picker overlay listing `output_dir` images
newest first, and a submit path that reuses the same `mpsc` result channel the Generate tab
already drains.

Purpose: ROADMAP success criterion 4 requires the edit flow on CLI, TUI and web with
equivalent results. The TUI is where this is most expensive to get wrong and least expensive
to notice: its row behaviour is spread across four `match` blocks that end in `unreachable!()`,
so an index that overruns a row count is a runtime panic the user hits as a black screen. That
makes the row table the thing to pin with tests, which is why this plan ends with a `#[cfg(test)]`
module in a file that currently has none.

Output: an Edit tab in `src/tui.rs` with tab-scoped state, a picker overlay, a comma-separated
reference field, submit through `generate_image_core`, and the first unit tests `src/tui.rs` has.
</objective>
